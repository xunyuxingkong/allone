# XG DB Test：进入正式主线前最后收口项清单

> 日期：2026-09-17  
> 适用仓库：`xunyuxingkong/allone`  
> 目的：明确进入 XGT Parser / Compiler / Catalog 正式主线前，最后需要处理的 **3 个 Contract 边界 + 1 个 Admission 范围声明 + 1 次 G0A Freeze 验收**。

## 1. 总体结论

此前真正严重的 P0 正确性问题已经基本修复。

当前不建议继续横向新增更多 Bootstrap Case、Worker 功能、完整 Lease/Fencing、完整 Reset/Probe 或外围工具。

进入正式主线前，只建议最后完成：

```text
1. Runtime Profile Identity Golden Vector 最后一轮
2. 真实 Xugu Driver Type Mapping 样本冻结
3. Typed Expected Union 边界测试与约束
4. Admission v0.1 支持范围声明
5. G0A Acceptance / Freeze
```

完成后直接进入：

```text
XGT Parser
→ Metadata Resolver
→ Compiler
→ Catalog 2
→ Selector / Test Plan
→ Manifest / Bundle
→ Formal Runner
```

## 2. Contract 边界一：Runtime Profile Identity 最后一轮冻结

### 当前状态

已经完成：

```text
Runtime Profile 语义身份与 Probe Evidence 分离
Host / Database Alias 不进入 Profile ID
时间戳、随机表名、运行 ID 等不进入 Profile ID
RuntimeProfileIdentity 已结构化
Profile ID 使用 XGMJ1 + SHA-256
Error Message 原文不直接参与 Identity
```

### 剩余问题

需要把“哪些变化应该影响 Profile ID、哪些不应该影响”用 Golden Vector 彻底锁死。

如果后续 Parser / Compiler / Manifest 已经依赖 `sql_runtime_profile_id` 后再改 Identity Projection，会影响：

```text
Target Identity
Manifest Identity
Baseline
Environment Compatibility
Result Reproducibility
```

### 必补 Golden Vector

不应改变 Profile ID：

```text
started_at
finished_at
probe_run_id
随机表名
随机对象名
Host
Database Alias
Raw Error Message 中具体对象名
Artifact 路径
Probe Duration
Server PID / Session ID
```

必须改变 Profile ID：

```text
DB Product
DB Version
DB Build
Driver Version
OS
Arch
Compatibility Mode
Configuration Fingerprint
Type Mapping 语义
Transaction Semantics
Error Mapping 稳定语义
Cancel Capability
Reset Capability
contract_set_id
```

### 修正方案

建立：

```text
framework_tests/contract/runtime_profile/
```

至少覆盖：

```text
stable_context_changes
semantic_changes
error_message_noise
contract_version_changes
```

### 验收标准

```text
同语义环境，多次 Probe -> 相同 Profile ID
语义发生变化 -> Profile ID 必须变化
```

完成后：

```text
Runtime Profile Identity = FROZEN
```

## 3. Contract 边界二：真实 Xugu Driver Type Mapping 样本冻结

### 当前状态

已经解决：

```text
Adapter 与 Comparator 共用 Logical Type Mapping
timestamp / time substring bug
长类型优先匹配
带参数类型识别
BOOLEAN / VARBINARY 等映射
```

### 剩余问题

当前很多测试仍主要验证字符串形式的 Driver Type Name，但真实：

```text
cursor.description[i][1]
```

可能返回字符串、类型对象、整数 type code 或 Driver 自定义对象。

### 风险

如果真实 Driver Metadata 和单测假设不同，会导致：

```text
Canonical Header 错误
Decimal/String 混淆
Timestamp/Time 混淆
Bytes/String 混淆
Hash 不一致
Exact Compare 误判
```

### 修正方案

在真实 Xugu 环境做一次 Driver Metadata Probe，覆盖至少：

```text
INT / INTEGER
BIGINT
SMALLINT
NUMERIC / DECIMAL / NUMBER
FLOAT / DOUBLE
CHAR / VARCHAR / TEXT
DATE
TIME
DATETIME / TIMESTAMP
TIMESTAMP WITH TIME ZONE（如支持）
BINARY / VARBINARY / RAW
BLOB
BOOLEAN（如支持）
```

每种类型记录：

```text
SQL Declared Type
cursor.description raw type
raw Python representation
normalized driver type
framework logical type
actual Python value type
canonical compatibility
```

建议输出：

```text
artifacts/xugu_driver_type_mapping.json
```

或：

```text
framework_tests/fixtures/xugu_driver_type_mapping_v1.json
```

### 验收标准

```text
每一种正式支持的 SQL 类型
→ 有真实 Driver Metadata 证据
→ 映射到唯一 Logical Type
```

未知类型必须：

```text
None / UNKNOWN
```

不能静默转成 string。

完成后冻结：

```text
Logical Type Mapping v1
```

## 4. Contract 边界三：Typed Expected Union 最后收口

### 当前状态

已有：

```text
ExpectedRows
ExpectedHash
ExpectedError
ExpectedStatement
```

并已修复：

```text
ExpectedError 空对象
ExpectedStatement affected_rows 可空
Rows Expected 误走 Error Comparator
```

### 剩余问题

Pydantic Union 在未来扩展时仍可能出现歧义匹配。

### 必须补的边界测试

必须拒绝：

```yaml
expected: {}
```

```yaml
expected:
  rows: []
  sha256: abc...
```

```yaml
expected:
  code: E1001
  rows:
    - [1]
```

```yaml
expected:
  affected_rows: -1
```

```yaml
expected:
  message_pattern: ""
```

```yaml
expected:
  code: ""
```

```yaml
expected:
  sqlstate: ""
```

必须明确是否合法：

```yaml
expected:
  rows: []
```

应明确是否表示合法 0 行结果。

还要明确：

```yaml
expected:
  rows:
    - []
```

是否表示 1 行 0 列。

### 推荐长期方案

正式 XGT Compiler 输出时使用明确类型，而不是 Runtime 猜：

```text
ExpectedRows
ExpectedHash
ExpectedError
ExpectedStatement
```

如需进一步显式化，可加入 discriminator：

```yaml
expected:
  kind: error
  code: E5021
```

### 验收标准

```text
每个 Expected 输入只能匹配一种类型
非法混合结构在 Compile/Validation 阶段拒绝
Comparator 不根据 dict key 猜 Expected 类型
```

完成后：

```text
Typed Expected Contract v1 = FROZEN
```

## 5. Admission v0.1：明确支持范围，不继续扩实现

### 当前状态

已实现：

```text
shared_read / shared_read -> 允许
write / exclusive 重叠 -> 冲突
same resource -> overlap
direct parent-child -> overlap
same owner -> 可豁免
```

### 当前问题

容易让后续开发者误以为完整 Resource Admission Engine 已经存在。

实际上当前还不支持：

```text
多级资源祖先
容量分配
Quantity 累计
原子 Lease 持久化
Fencing Token
Concurrent Reservation
Cluster Drain
Environment Capacity
跨进程资源锁
```

### 修正方案

明确命名和版本：

```text
Admission Conflict Rules v0.1
```

v0.1 支持：

```text
same resource identity
direct parent-child
shared_read
shared_write
exclusive
same-owner bypass
pure deterministic evaluation
```

v0.1 不支持：

```text
multi-level ancestor traversal
capacity / quantity allocation
persistent reservation
lease
fencing
distributed concurrency
cluster draining
```

### 推荐测试

继续覆盖：

```text
READ/READ
READ/WRITE
WRITE/READ
EXCLUSIVE
direct parent
unrelated resources
same owner
```

并增加边界测试，明确：

```text
grandparent currently not expanded
quantity currently not enforced
```

### 验收标准

所有调用方清楚：

```text
Admission v0.1
```

只是静态 Conflict Rule，不是完整 Lease/Resource Manager。

完成这一步后，不继续阻塞主线。

